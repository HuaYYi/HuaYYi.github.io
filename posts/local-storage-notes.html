浏览器里的数据库：localStorage 使用心得与陷阱

这个博客的本地模式把文章全存在 localStorage 里——不连服务器、不要令牌，关掉浏览器再打开文章还在。它是最容易被低估的浏览器能力之一：API 只有五个方法，但坑一个不少。

30 秒速览

localStorage.setItem('key', 'value'); // 存（值只能是字符串）
localStorage.getItem('key');           // 取，不存在返回 null
localStorage.removeItem('key');        // 删单个
localStorage.clear();                  // 清空整个来源！
localStorage.length;                   // 键值对数量

它按「来源」（协议 + 域名 + 端口）隔离：localhost 和线上域名互不可见，不同端口也算不同来源。数据永久保存，除非用户清缓存或代码删除。

陷阱一：容量只有约 5MB，且按 UTF-16 计

localStorage 的容量配额通常按 UTF-16 编码计算，也就是一个非 BMP 字符（比如部分 emoji）要占 4 字节。存纯文本问题不大，但本站本地模式允许把图片转成 dataURL 存进去——base64 会让体积膨胀约 33%，几张高清图就能把配额吃满。所以写入大图前先提醒用户，存图优先走仓库 assets/images/ 而不是 localStorage。

陷阱二：结构化数据要自己序列化

值只能是字符串，存对象要 JSON.stringify，取出来 JSON.parse。两处经典翻车：

  • 忘记 stringify，存进去的是 "[object Object]"，取出来哭都来不及；
  • JSON.parse(null) 会返回 null 没问题，但 parse 遇到损坏的字符串会抛异常。所以读取必须包 try/catch，本站的写法是解析失败就回退到空数组，绝不让一份数据坏掉拖垮整个页面。

陷阱三：clear() 是核弹

同一来源下所有应用的键共用一个 localStorage。如果你的页面嵌在别人的域下（或反过来），clear() 会把不相关的数据一起带走。正确姿势是键名加前缀 + 按前缀遍历删除：

// 只删自己的键：本站所有键都以 ssb. 开头
for (var i = localStorage.length - 1; i >= 0; i--) {
  var k = localStorage.key(i);
  if (k.indexOf('ssb.') === 0) localStorage.removeItem(k);
}

倒序遍历是因为删除会改变索引，正序删会漏。本站角标上的「清空缓存」按钮就是按这个思路实现的：删 ssb.local.posts 和全部 ssb.local.content.*，不碰搜索引擎选择等其他前缀的键。

什么时候不该用它

  • 数据需要跨设备同步 → 它只在单个浏览器里存在；
  • 数据量大或需要检索排序 → 上 IndexedDB；
  • 敏感信息（令牌之类）→ XSS 可直接读到，能不放就不放；
  • 只是临时记住 UI 状态 → 它反而合适，但记得存版本号，将来结构变了好迁移。

写满了怎么办：QuotaExceededError

setItem 超配额时不是静默失败，而是抛异常。如果不 try/catch，保存动作会直接报错中断，用户还不知道文章没存上。稳妥写法：

try {
  localStorage.setItem(key, JSON.stringify(data));
} catch (err) {
  alert('本地存储空间已满，请清理图片或导出后删除旧文章');
}

更进一步可以在写入前估算大小：new Blob([value]).size 拿到 UTF-8 字节数，配合 navigator.storage.estimate()（返回配额与已用量，支持度不错）提前预警，而不是等写崩了再说。

多标签页同步：storage 事件

同一个来源开了两个标签页，A 页改了 localStorage，B 页怎么知道？浏览器会在其他标签页触发 storage 事件（注意：改动它的那个页面本身不触发）：

window.addEventListener('storage', function (e) {
  if (e.key === 'ssb.local.posts') {
    refreshPostList();   // e.newValue 就是新值，免一次读取
  }
});

一个标签页写内容、另一个标签页开着列表的场景，靠这个事件就能做到「一处保存，另一处自动出现」，不需要轮询。

三兄弟怎么选

能力localStoragesessionStorageIndexedDB
生命周期永久（手动清除前）标签页关闭即清永久
容量约 5MB约 5MB通常百 MB 起
数据类型字符串字符串对象/Blob/文件
典型场景配置、草稿、小缓存表单暂存、跳转传参离线数据、图片库

本站的取舍：文章正文是 HTML 字符串、单篇几十 KB，localStorage 够用；图片 dataURL 是容量杀手，所以明确提示走仓库上传，而不是什么都往里塞——工具选型先看数据形态，再看 API 顺手程度。

localStorage 像抽屉：小、方便、就在手边。放对东西它是救星，放错东西它是隐患——关键是你得知道它的边界。
