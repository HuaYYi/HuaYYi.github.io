博客的第一印象：标题与摘要怎么写

读者在归档页或搜索引擎看到你的文章，最先看到的就是标题和摘要。这两个元素决定了读者是否点进来——写得好，点击率翻倍；写得差，再好的内容也没人看。这篇文章聊聊我总结的几个原则。

标题：说清「是什么」和「为什么」

好的技术博客标题要同时回答两个问题：这篇文章讲什么？读了有什么用？比如：

  • 差标题：《CSS 学习笔记》（太空泛，不知道讲哪个方面）
  • 好标题：《CSS Grid 实战：用网格做响应式卡片墙》（明确主题 + 明确场景）
  • 差标题：《localStorage 使用心得》（没有信息量）
  • 好标题：《浏览器里的数据库：localStorage 使用心得与陷阱》（点出「数据库」这个类比，暗示深度）

标题里的关键词也很重要——「实战」「指南」「笔记」「心得」这些词会直接影响读者的预期。如果你想写「教程」，就用「实战」或「指南」；如果是「经验总结」，就用「心得」或「陷阱」。

摘要：一句话说清核心价值

摘要的作用是「让读者 3 秒内判断这篇文章值不值得读」。我给自己定的标准是：

  • 长度控制在 60~100 字，超出会被截断；
  • 必须包含「问题 + 方案」或「现象 + 结论」；
  • 避免空洞的形容词（「深入」「全面」「详细」），用具体数字和事实代替。

举个例子，这篇文章的摘要初版是《聊聊博客标题和摘要的写作技巧》——太空泛了。改成现在的版本后，明确告诉读者「你将学到标题和摘要的具体写法，以及为什么这样写」。

标题与摘要的配合

标题和摘要应该互补，而不是重复。标题说「是什么」，摘要说「为什么」；标题抛出问题，摘要给出答案方向。比如：

标题：《CSS 变量工程化实践》
摘要：《只配置一个 #1d6ff2，hover 深色、浅底高亮全由程序混色算出。聊聊 CSS 变量 + 运行时注入的配色系统怎么搭。》

标题点明主题（CSS 变量），摘要给出核心价值（一套配色方案 + 工程化方法）。读者看完摘要，已经知道这篇文章能解决什么问题了。

写完之后，自己先读一遍

最后一步是「自查」：把标题和摘要读出来，问自己三个问题：

  1. 我能在 3 秒内说出这篇文章讲什么吗？
  2. 我能说出「读了有什么用」吗？
  3. 如果我是读者，我会点进来吗？

如果三个问题有任何一个答不上来，就重写。标题和摘要不是「写完正文再补的」，它们是文章的一部分，值得花 10% 的时间打磨。

标题是承诺，摘要是证据。读者点进来，是因为相信你承诺的东西值得看。
